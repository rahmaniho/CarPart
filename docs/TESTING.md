# راهبرد آزمون — کارپارت

## لایه‌ها
1. **تست واحد** (منطق محض): پول/درصد، نرمال‌سازی متن فارسی، قیمت‌گذاری، رتبه‌بندی، ماشین حالت سفارش
2. **تست سرتاسری API** (Jest + supertest): جریان‌های واقعی روی پایگاه‌داده درون‌حافظه‌ای
3. **تست UI** (Vitest + Testing Library): فرم‌ها، هدایت نقش‌محور، اجزا
4. **آزمون دود زنده** (`scripts/smoke_e2e.py`): ۵۱ بررسی روی سرور در حال اجرا

## اجرا
```bash
npm run test -w @carpart/api          # ۱۰ مجموعه / ۷۵ تست
npm run test -w @carpart/api-client   # ۸ تست
npm run test -w @carpart/mobile       # ۱۲ تست
npm run test -w @carpart/web          # ۸ تست
python3 scripts/smoke_e2e.py          # ۵۱ بررسی
```

## سناریوهای پوشش‌داده‌شده (API)
- **چرخه سفارش ۱–۱۰:** قیمت‌گذاری سمت سرور، رد فیلد ناشناخته، رزرو اتمیک/جلوگیری از oversell، Idempotency، پرداخت Sandbox + کمیسیون ۷٪، امضای جعلی، انقضای بدون پرداخت، گذار غیرمجاز، دسترسی بین‌کاربری، کوپن، مهلت بازپرداخت
- **RFQ ۱۱–۱۷:** دروازه پروفایل، مهلت/هدف‌گیری، دید فروشنده، رد پس از مهلت، پذیرش → سفارش + رد بقیه + replay-guard، انقضای خودکار
- **ارسال ۱۸–۲۲:** ساخت مأموریت/پیشنهاد، رد دسترسی پیک دیگر، مهلت و تعویض، کد/OTP (غلط/درست)، ماسک حریم خصوصی
- **امنیت ۲۳–۳۴:** ۴۰۱/کد خطا، چرخش رفرش + ابطال، RBAC اپراتور/مدیر، ممیزی تنظیمات، بازه تنظیمات، فروشنده تأییدنشده، داده عمومی، اعتبارسنجی فارسی، اعلان + SMS شبیه‌سازی، تغییر نقش، آپلود نامعتبر
- **محدودسازی نرخ ۳۵–۳۶:** ۴۲۹ ساخت‌یافته + حد سخت‌گیرانه auth
- **RFQ اعلان ۳۷:** متن/لینک واقعی اعلان + اعلان مستقل هر پیشنهاد + حذف تکرار

## قراردادهای تست
- تست‌های e2e روی یک DB مشترک‌اند → مقایسه‌های نسبی (delta)؛ `expireUnpaidPayments` همه سفارش‌های معلق را جارو می‌کند.
- `THROTTLE_DISABLED=true` در تست‌ها (تکرارپذیری) + مجموعه جدا برای اثبات خود مکانیزم.
- تست‌ها دقیقاً با همان پیکربندی زمان اجرا (`configureApp`) بوت می‌شوند.
