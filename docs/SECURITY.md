# ملاحظات امنیتی — کارپارت

## احراز هویت و نشست
- توکن دسترسی (JWT) فقط در هدر `Authorization` — **هرگز در کوکی** (حذف ریسک CSRF).
- رفرش توکن در کوکی `httpOnly` + `SameSite=Strict` + `Secure` (در HTTPS) با **چرخش** و ابطال نشست در استفاده مجدد (تشخیص سرقت).
- رمز عبور با `crypto.scrypt` + salt (بدون bcrypt/argon2 — ساخت native ناممکن در محیط توسعه؛ مستند و قابل تعویض).
- OTP: انقضای کوتاه، سقف تلاش، محدودسازی نرخ روی `/auth/otp/request`.

## مجوزدهی
- سرور مرجع است: گاردهای `Roles` + `RequirePermissions` روی همه مسیرهای حساس؛ مخفی کردن دکمه در UI کافی نیست.
- جداسازی نقش‌ها: اپراتور `order:read:all` دارد اما **بدون** دسترسی مالی/تنظیمات/تأیید هویت/ممیزی.
- دسترسی بین‌کاربری: `assertReadAccess` برای سفارش/درخواست/مأموریت (کاربر متقاطع ۴۰۳/۴۰۴، مدیر با مجوز مجاز).

## یکپارچگی داده و پرداخت
- قیمت/وضعیت/مبلغ **هرگز از کلاینت** پذیرفته نمی‌شود؛ فیلدهای ناشناخته با `forbidNonWhitelisted` رد می‌شوند.
- تأیید پرداخت فقط از مسیر سمت سرور (`POST /payments/verify` یا Sandbox)؛ امضای HMAC درگاه Sandbox با مقایسه امن (`safeEqual`).
- Idempotency-Key برای پرداخت/سفارش/تسویه (جلوگیری از تکرار/پخش مجدد).
- رزرو موجودی اتمیک + کاهش هم‌زمانی با شرط موجودی (بدون فروش بیش از موجودی).
- اطلاعات بانکی فروشندگان رمزنگاری‌شده (`encryptSecret`) و هرگز خام برنمی‌گردد.

## حریم خصوصی و اطلاعات
- ماسک شماره تماس/نام مشتری برای پیک/غیرمالک در رهگیری ارسال.
- حذف خودکار موقعیت پیک پس از ۲۴ ساعت.
- کد تحویل/OTP در `deliveries` رمزنگاری‌شده نگهداری می‌شود.
- گزارش ممیزی (audit log) برای عملیات حساس: تغییر تنظیمات/نقش/تأیید هویت/بازپرداخت.

## ورودی و خروجی
- ValidationPipe سراسری (class-validator) با پیام فارسی ساخت‌یافته per-field.
- محافظت XSS: React (escaping پیش‌فرض) + `helmet`؛ CSP عمداً در توسعه باز است (باید در استقرار سخت شود — در STATUS ثبت شده).
- آپلود فایل: اعتبارسنجی magic bytes + سقف حجم + نوع مجاز (فقط local storage در MVP).
- محدودسازی نرخ (Throttler) با حد سخت‌گیرانه‌تر برای مسیرهای auth؛ پاسخ ۴۲۹ ساخت‌یافته.

## وابستگی‌های خارجی
- هیچ API key فرضی در کد نیست؛ همه از env خوانده و اعتبارسنجی می‌شوند (zod).
- حالت‌های mock/sandbox صادقانه در پاسخ‌ها علامت می‌خورند (`isSimulated`, `routeSource`, `sandboxActive`).
