# ردیابی زنده پیک با GPS

## جریان عملیاتی

1. پیک یک مأموریت را می‌پذیرد.
2. تا وقتی صفحه مأموریت باز و وضعیت آن فعال است، اپ پیک تقریباً هر ۱۵ ثانیه نمونه GPS را همراه شناسه مأموریت به API می‌فرستد.
3. API مالکیت مأموریت، وضعیت فعال، تازگی نمونه و محدوده مختصات را سمت سرور بررسی می‌کند.
4. خریدار و فروشنده همان سفارش، آخرین موقعیت مجاز را تقریباً هر ۱۰ ثانیه دریافت می‌کنند.
5. وقتی پیک با GPS معتبر وارد شعاع فروشگاه شود، رسیدن او فقط یک‌بار ثبت و اعلان آماده‌سازی بسته برای فروشنده ایجاد می‌شود.
6. بعد از تحویل، لغو یا شکست مأموریت، اپ Watch را متوقف می‌کند و API نیز نمونه جدید را رد می‌کند.

## دسترسی و حریم خصوصی

- فقط پیک تخصیص‌یافته اجازه ارسال موقعیت برای مأموریت را دارد.
- فقط مالک سفارش، فروشنده همان سفارش و مدیر/اپراتور مجاز به مشاهده ردیابی‌اند.
- موقعیت عمومی پیک برای دیگر کاربران قابل مشاهده نیست.
- تاریخچه موقعیت طبق تنظیم `courier.location.retention_hours` پاکسازی می‌شود.
- نمونه‌های قدیمی‌تر از دو دقیقه یا نمونه‌های دارای زمان آینده رد می‌شوند.
- اعلان رسیدن با کلید یکتا ثبت می‌شود و با ارسال‌های GPS بعدی تکرار نمی‌شود.

## تنظیمات قابل تغییر مدیر

| کلید | پیش‌فرض | توضیح |
|---|---:|---|
| `courier.location.arrival_radius_m` | ۳۰۰ متر | شعاع تشخیص رسیدن به فروشگاه |
| `courier.location.max_accuracy_m` | ۱۵۰ متر | بیشترین خطای GPS مجاز برای فعال‌شدن Geofence |
| `courier.location.fresh_seconds` | ۴۵ ثانیه | پس از این زمان، رابط موقعیت را قدیمی نشان می‌دهد |
| `courier.location.retention_hours` | ۲۴ ساعت | مدت نگهداری نمونه‌های موقعیت |

## نقشه و سرویس‌های بیرونی

کارت داخل اپ بدون وابستگی به ارائه‌دهنده خارجی، مسیر را به‌صورت شماتیک نشان می‌دهد. دکمه «باز کردن موقعیت پیک در نقشه» از برنامه نقشه دستگاه استفاده می‌کند. مسیریابی و ETA همچنان از آداپتر قابل تنظیم `MAP_PROVIDER` استفاده می‌کنند و هیچ API Key در برنامه یا مخزن قرار نمی‌گیرد.

## اعلان فروشنده

رویداد `delivery.arrived_at_seller` روی کانال درون‌برنامه‌ای فعال است. Push واقعی فقط وقتی عملیاتی است که موارد زیر پیکربندی شده باشند:

- `PUSH_PROVIDER=fcm`
- کلید سرور FCM در Secret محیط اجرا
- `google-services.json` در فرایند امن Build اپ Android
- ثبت موفق Device Token فروشنده

در غیر این صورت اعلان درون‌برنامه‌ای ثبت می‌شود و Push در حالت تنظیم‌نشده عملیاتی ادعا نمی‌شود.

## محدودیت ردیابی پس‌زمینه

نسخه جاری از Capacitor Geolocation استفاده می‌کند و ردیابی پیوسته را **هنگام باز و فعال بودن صفحه مأموریت** انجام می‌دهد. Android در پس‌زمینه ممکن است اجرای WebView را محدود کند. ردیابی تضمینی پس‌زمینه نیازمند Foreground Service نیتیو، اعلان دائمی، سیاست حریم خصوصی و آزمون باتری روی دستگاه واقعی است و در نسخه جاری فعال اعلام نمی‌شود.
