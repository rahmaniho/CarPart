# طراحی پایگاه‌داده و مدل داده (Database Schema & Data Model)

## ۱. سازگاری دوگانه پایگاه‌داده

لایه داده با **TypeORM** به‌گونه‌ای پیاده‌سازی شده است که هم با **PostgreSQL 16** (محیط عملیاتی و Docker Compose) و هم با **SQLite مبتنی بر `sql.js`** (محیط توسعه سریع، CI و آزمون‌های E2E بدون پیش‌نیاز خارجی) صددرصد سازگار است.

---

## ۲. گروه‌بندی جداول اصلی سامانه

### الف) هویت، دسترسی و امنیت
- `users`: اطلاعات پایه کاربر، شماره موبایل یکتا (`09xxxxxxxxx`)، هش رمز عبور (`bcrypt`)، آرایه نقش‌ها و وضعیت حساب.
- `auth_sessions`: نشست‌های فعال، هش توکن رفرش چرخشی، IP، مشخصات مرورگر، زمان انقضا و ابطال.
- `otp_codes`: کدهای یکبارمصرف هش‌شده، شمارنده تلاش ناموفق و مهلت انقضا.

### ب) پروفایل‌های تجاری سه ضلع بازار
- `workshops`، `workshop_addresses`، `workshop_vehicles`، `favorites`: اطلاعات تعمیرگاه، مختصات آدرس‌های تحویل و خودروهای ذخیره‌شده.
- `sellers`، `seller_branches`: اطلاعات فروشگاه، وضعیت احراز هویت، امتیاز عملکرد، اطلاعات شبا رمزنگاری‌شده (`AES-256-GCM`) و شعبه‌ها با شعاع پوشش و ساعات کاری.
- `courier_profiles`، `courier_locations`: مشخصات وسیله نقلیه پیک، وضعیت آنلاین/آفلاین، اطلاعات شبا رمزنگاری‌شده و نقاط مکانی مأموریت فعال.

### ج) کاتالوگ استاندارد، سازگاری و انبار فروشنده
- `categories` (درختی خودارجاع)، `brands`: درخت دسته‌بندی قطعات و برندهای سازنده.
- `vehicle_makes`، `vehicle_models`، `vehicle_variants`: سلسله‌مراتب استاندارد خودروهای بازار ایران.
- `parts`، `part_compatibilities`: کاتالوگ مرجع قطعه (شامل `search_key` نرمال‌شده فارسی، کد فنی و OEM) و قواعد تطابق با تیپ/سال/موتور خودرو.
- `seller_products`: پیشنهاد فروش هر شعبه شامل `price`، `stock`، `reserved_stock`، `quality` و `preparation_minutes`.
- `inventory_movements`: **دفتر تغییرناپذیر حرکت موجودی** (`restock`، `reserve`، `release`، `commit`، `return`، `adjustment`) برای ردیابی دقیق هر تغییر عدد موجودی.

### د) استعلام قیمت (RFQ)، سفارش، پرداخت و مالی
- `part_requests`، `quotes`، `quote_items`: چرخه کامل استعلام رقابتی قیمت و اقلام پیشنهادی فروشندگان (شامل علامت قطعه جایگزین `is_substitute`).
- `orders`، `order_items`، `order_events`: سفارش با تصویر لحظه‌ای (`Snapshot`) آدرس، خودرو و قیمت اقلام در لحظه ثبت به همراه تاریخچه کامل رویدادها.
- `payments`، `refunds`: تراکنش‌های پرداخت، شناسه مرجع درگاه و پرونده‌های استرداد وجه.
- `commission_records`، `payouts`، `coupons`: دفتر محاسبه کارمزد پلتفرم، سهم خالص فروشنده/پیک، دسته‌های تسویه شبا و کوپن‌های تخفیف.

### هـ) لجستیک، پشتیبانی و حاکمیت
- `deliveries`، `delivery_events`: مأموریت‌های ارسال پیک، کدهای محرمانه `pickup_code` و `delivery_otp`، مسافت و زمان تحویل.
- `reviews`، `tickets`، `ticket_messages`، `return_requests`: دیدگاه‌های خریداران واقعی، تیکت‌های پشتیبانی و پرونده‌های مرجوعی کالا.
- `system_settings`، `announcements`، `audit_logs`، `idempotency_records`: تنظیمات پویا، اطلاعیه‌های سراسری، لاگ حسابرسی تغییرناپذیر و کلیدهای جلوگیری از تکرار تراکنش.

## ۳. دستورات مدیریت پایگاه‌داده

```bash
npm run db:migrate   # اجرای مهاجرت‌ها / همگام‌سازی ساختار جداول
npm run db:seed      # درج داده‌های نمونه غنی و واقع‌گرایانه فارسی (قابل اجرای مجدد / Idempotent)
```
