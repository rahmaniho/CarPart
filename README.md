# قطعه‌رسان (CarPart) — پلتفرم هوشمند تأمین و ارسال سریع لوازم یدکی خودرو

**قطعه‌رسان (CarPart)** یک پلتفرم بازارگاه چندوجهی (Multi-Sided B2B/B2C Marketplace) تمام‌راست‌به‌چپ (RTL) و بومی‌سازی‌شده برای بازار لوازم یدکی خودرو در ایران است که **تعمیرگاه‌ها و مکانیک‌ها** را به **فروشندگان احرازهویت‌شده لوازم یدکی** و **ناوگان پیک شهری** متصل می‌کند.

این مخزن به شکل یک Monorepo تایپ‌اسکریپتی یکپارچه طراحی شده است که در آن یک بسته قرارداد مشترک (`@carpart/contract`) میان سرویس بک‌اند (`NestJS + TypeORM`) و برنامه وب (`React 18 + Vite + Tailwind CSS`) به اشتراک گذاشته شده تا هیچ ناهماهنگی‌ای میان انواع داده، وضعیت‌ها، مجوزها، واحد پول (عدد صحیح تومان) و تقویم جلالی به وجود نیاید.

## ویژگی‌های کلیدی معماری و محصول

1. **دو مسیر واقعی تأمین قطعه**:
   - **مسیر اول — خرید مستقیم از کاتالوگ**: جست‌وجوی مقاوم به نویسه‌های فارسی/عربی (`ی/ي`، `ک/ك`، نیم‌فاصله و ارقام فارسی)، بررسی خودکار سازگاری قطعه با تیپ خودرو، رزرو اتمیک موجودی انبار و ثبت سفارش تک‌فروشنده‌ای با کلید یکتاسازی (`Idempotency-Key`).
   - **مسیر دوم — استعلام رقابتی قیمت (RFQ)**: ثبت درخواست تأمین توسط مکانیک برای قطعات کمیاب یا دارای ابهام فنی، ارسال هدفمند به فروشندگان تأییدشده هم‌شهر، دریافت پیشنهادهای چندگانه (اصلی یا جایگزین)، رتبه‌بندی شفاف و تبدیل مستقیم پیشنهاد منتخب به سفارش رسمی.
2. **چهار پنل تخصصی مبتنی بر نقش (RBAC سرور و کلاینت)**:
   - **پنل مکانیک / تعمیرگاه (`/mechanic`)**: مدیریت گاراژ و آدرس‌ها، پیگیری سفارش، درگاه آزمایشی شفاف، مشاهده کد تحویل یکبارمصرف (`OTP`)، ثبت دیدگاه و مرجوعی.
   - **پنل فروشنده قطعه (`/seller`)**: مدیریت شعبه‌ها و محصولات، به‌روزرسانی اتمیک قیمت و موجودی با دفتر حرکت انبار، پاسخ به استعلام‌ها، آماده‌سازی سفارش، مشاهده کد تحویل به پیک (`Pickup Code`) و گزارش کارمزد/تسویه.
   - **پنل پیک ناوگان (`/courier`)**: تغییر وضعیت آنلاین/آفلاین، ثبت موقعیت مکانی با رعایت حریم خصوصی، پذیرش مأموریت، دریافت بسته با کد ۵ رقمی فروشنده و تکمیل تحویل با کد OTP خریدار.
   - **پنل مدیریت و اپراتور پشتیبانی (`/admin`)**: داشبورد واقعی پایگاه‌داده (تفکیک صریح **گردش ناخالص GMV** از **درآمد خالص کارمزد پلتفرم**)، احراز هویت فروشندگان و پیک‌ها، دیسپاچ دستی پیک، مدیریت کاتالوگ مرجع، کوپن‌ها، تسویه‌ها، داوری مرجوعی، تنظیمات زنده سیستم و لاگ حسابرسی تغییرناپذیر (`Audit Log`).
3. **شفافیت کامل زیرساخت‌های شبیه‌سازی‌شده (Sandbox Honesty)**:
   - در محیط توسعه، درگاه پرداخت (`sandbox`)، پیامک (`mock`) و مسیریابی (`mock` Haversine) به شکل شفاف در بنر وضعیت بالای سامانه و خروجی `/health/ready` و `/api/v1/public/settings` اعلام می‌شوند و با تغییر متغیرهای محیطی به آداپتورهای واقعی (`Zarinpal`، `Kavenegar`، `OSRM/Neshan`، `S3/MinIO`، `PostgreSQL`) سوییچ می‌کنند.

## ساختار Monorepo

```text
CarPart/
├── packages/
│   └── contract/          # قرارداد مشترک: نقش‌ها، مجوزها، ماشین وضعیت، تومان صحیح، تقویم جلالی، نرمال‌ساز فارسی
├── apps/
│   ├── api/               # بک‌اند ماژولار NestJS 10 + TypeORM (پشتیبانی هم‌زمان PostgreSQL و SQLite) + Swagger
│   └── web/               # فرانت‌اند React 18 + Vite 6 + Tailwind RTL + فونت محلی Vazirmatn + Recharts
├── scripts/
│   ├── check-contract.mjs # بررسی خودکار انطباق ۱۰۰٪ مسیرهای کلاینت با کنترلرهای NestJS
│   └── smoke_e2e.py       # آزمون دود سرتاسری زنده روی سرور واقعی برای هر ۵ نقش
├── docs/                  # مستندات جامع مهندسی، معماری، پایگاه‌داده، API، امنیت و استقرار
├── Dockerfile             # ساخت چندمرحله‌ای ایمیج‌های api و web (Nginx)
└── docker-compose.yml     # استقرار کامل PostgreSQL + API + Web
```

## راه‌اندازی سریع در محیط توسعه (بدون نیاز به سرویس خارجی)

### پیش‌نیازها
- **Node.js 20+** و **npm 10+**
- (اختیاری) **Python 3.10+** برای اجرای اسکریپت آزمون سرتاسری `scripts/smoke_e2e.py`

### گام‌های اجرا

```bash
# ۱. نصب وابستگی‌های کل Monorepo
npm install

# ۲. ایجاد فایل متغیرهای محیطی بک‌اند (SQLite توکار + درگاه‌های آزمایشی شفاف)
cp apps/api/.env.example apps/api/.env

# ۳. ساخت همه بسته‌ها و تزریق داده‌های نمونه غنی فارسی (Seed)
npm run build
npm run db:seed

# ۴. اجرای هم‌زمان بک‌اند (پورت ۴۰۰۰) و فرانت‌اند Vite (پورت ۵۱۷۳ با پروکسی داخلی /api)
npm run dev:api   # در ترمینال اول
npm run dev:web   # در ترمینال دوم
```

- **رابط وب سامانه**: `http://localhost:5173`
- **مستندات تعاملی Swagger API**: `http://localhost:4000/api/docs`
- **بررسی سلامت سرویس**: `http://localhost:4000/health` و `http://localhost:4000/health/ready`

## حساب‌های نمونه آماده آزمون (پس از `npm run db:seed`)

در صفحه `/login` دکمه‌های **«ورود سریع توسعه»** برای هر ۵ نقش تعبیه شده است؛ همچنین امکان ورود با رمز عبور یا کد OTP توسعه فراهم است:

| نقش کاربری | نام نمونه | شماره موبایل | رمز عبور |
|---|---|---|---|
| **مدیر کل پلتفرم (`admin`)** | مدیر سامانه | `09120000000` | `ChangeMe!12345` |
| **اپراتور پشتیبانی (`operator`)** | سارا احمدی | `09120000001` | `CarPart!12345` |
| **مکانیک / تعمیرگاه (`mechanic`)** | رضا محمدی | `09121110001` | `CarPart!12345` |
| **فروشنده قطعه (`seller`)** | حسین رحیمی | `09122220001` | `CarPart!12345` |
| **پیک ناوگان (`courier`)** | مهدی قاسمی | `09123330001` | `CarPart!12345` |

کوپن‌های تخفیف نمونه فعال: `WELCOME10` (۱۰٪ تا سقف ۲۰۰ هزار تومان برای سفارش بالای ۳۰۰ هزار تومان) و `TEHRAN50` (۵۰ هزار تومان ثابت برای سفارش بالای ۲۰۰ هزار تومان).

## دستورات کنترل کیفیت و آزمون

```bash
npm run check:contract   # تطبیق خودکار قرارداد و مسیرهای API بین فرانت‌اند و بک‌اند
npm run typecheck        # بررسی سخت‌گیرانه TypeScript در هر سه بسته
npm run lint             # اجرای ESLint در بک‌اند و فرانت‌اند
npm run build            # کامپایل کامل تولیدی contract، api و web
npm test                 # اجرای تمام آزمون‌های واحد و یکپارچه (Jest + Vitest)
python3 scripts/smoke_e2e.py  # آزمون زنده چرخه کامل سفارش، پرداخت، استعلام و تحویل OTP
```
